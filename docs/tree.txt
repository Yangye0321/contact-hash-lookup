通讯录哈希查找系统程序流程描述
================================

一、程序组成
------------
1. HashContacts.cpp
   程序入口 main 函数，负责初始化哈希表、读取用户选择、显示菜单、调用各项功能以及退出时保存数据。

2. Functions.h
   定义哈希表节点 HashNode、桶 Buckets 和功能类 Functions。
   HashNode 保存姓名、电话号码、地址、查找次数、序号以及链表指针。

3. functions.cpp
   实现 BKDR 哈希、链地址法建表、插入、查询、模糊查询、删除、遍历、文件读写、平均查找长度统计和清空哈希表等功能。

4. contact.txt
   保存联系人数据。第一行是联系人数量，后续每行依次保存：姓名、电话号码、地址。


二、总体流程
------------

程序启动
  |
  v
创建 Functions 对象
  |
  v

  |
  v

  |-- 2：按电话号码查询

  +--> 6 更改查询方式

三、哈希表初始化流程
--------------------
1. 常量 Maxsize 设置为 53，表示哈希表有 53 个桶。
2. 每个桶创建一个头结点，头结点不存放实际联系人。
3. 头结点的 next 指针设置为空，表示该桶暂时没有联系人。
4. 头结点的 st 设置为 0。
5. 实际联系人通过 next 指针连接在头结点之后，形成链表。


四、BKDR 哈希流程
-----------------
输入：一个姓名或电话号码字符串

1. 设置 seed = 131，hash 初值为 0。
2. 从左到右遍历字符串中的每个字符。
3. 每读取一个字符，执行：
      hash = hash * 131 + 当前字符
4. 字符串遍历结束后，执行：
      哈希地址 = hash % 53
5. 哈希地址决定联系人所在的桶。

当多个联系人得到相同哈希地址时，它们会被放入同一个桶的链表中，这就是链地址法解决冲突。


五、读取文件并建立哈希表
------------------------
调用：ReadData -> CreateHash

1. 打开 contact.txt 进行输入。
2. 读取第一行的联系人数量 n。
3. 创建长度为 n 的临时 HashNode 数组。
4. 依次读取每个联系人的姓名、电话号码和地址。
5. 根据当前查询方式选择关键字：
   - 按姓名查询：使用 name 计算哈希地址。
   - 按电话号码查询：使用 pn 计算哈希地址。
6. 将联系人插入对应桶的链表尾部。
7. 新节点的 st 设置为当前链表长度加 1，表示查找到该节点需要经过的节点数。
8. 所有数据插入完成后，调用 SortHash 重新设置联系人序号。
9. 关闭文件并释放临时数组。


六、菜单功能流程
----------------

1. 查询
~~~~~~~~
按姓名查询：
1. 输入姓名。
2. 对姓名执行 BKDR 哈希，定位目标桶。
3. 从该桶的链表头开始逐个比较 name。
4. 如果找到完全相同的姓名，输出联系人信息并结束查询。
5. 如果目标桶中没有精确匹配，执行模糊查询。
6. 模糊查询会遍历所有桶，输出姓名中包含输入关键字的联系人。
7. 如果仍未找到，输出 Not found!。

按电话号码查询：
1. 输入电话号码。
2. 对电话号码执行 BKDR 哈希，定位目标桶。
3. 逐个比较 pn。
4. 找到完全相同的电话号码后输出联系人信息。
5. 精确查询失败时，遍历全部桶进行电话号码包含匹配的模糊查询。


2. 添加
~~~~~~~
1. 输入姓名、电话号码和地址。
2. 创建新的 HashNode。
3. 计算哈希地址并找到目标桶。
4. 将新节点连接到目标桶链表尾部。
5. 新节点的查找次数 st 设置为该链表当前长度加 1。
6. 调用 SortHash 重新编号。
7. 返回菜单。

注意：当前实现的 InsertHash 始终使用联系人姓名计算哈希地址，即使当前查询方式选择的是电话号码，添加操作仍按姓名放入桶中。


3. 删除
~~~~~~~
按姓名删除：
1. 输入姓名。
2. 根据姓名计算哈希地址。
3. 在目标桶链表中查找姓名完全相同的节点。
4. 找到后摘除该节点并释放内存。
5. 调整后续节点的 st 值。
6. 输出 Deleted!，重新编号后返回菜单。
7. 如果没有找到，输出 Not found!。

按电话号码删除：
1. 输入电话号码。
2. 根据电话号码计算哈希地址。
3. 在目标桶链表中查找电话号码完全相同的节点。
4. 找到后摘除节点、释放内存、调整后续节点查找次数并重新编号。
5. 如果没有找到，输出 Not found!。


4. 显示所有联系人
~~~~~~~~~~~~~~~~~~
1. 输出表头：序号、姓名、电话号码、地址、查找次数。
2. 从第 0 个桶遍历到第 52 个桶。
3. 依次访问每个桶链表中的节点。
4. 使用 visit1 输出每个联系人。
5. 显示顺序是哈希桶顺序和链表顺序，不是按姓名或电话号码排序。


5. 计算平均搜索长度
~~~~~~~~~~~~~~~~~~~~
1. TraverseHash(con, 3) 遍历所有节点，将每个节点的 st 累加得到查找次数总和。
2. TraverseHash(con, 2) 遍历所有节点，统计联系人总数。
3. 如果联系人数量为 0，输出“通讯录为空！”。
4. 否则计算：
      平均搜索长度 = 查找次数总和 / 联系人总数
5. 输出平均搜索长度。


6. 更改查询方式
~~~~~~~~~~~~~~~~
1. 输出提示信息。
2. 将当前菜单循环标志 off 设置为 false。
3. 调用 WriteData，将当前哈希表中的联系人保存到 contact.txt。
4. 调用 ClearHash，释放当前哈希表中的所有联系人节点。
5. 结束当前功能菜单循环。
6. 重新回到查询方式选择界面。
7. 用户重新选择按姓名或按电话号码查询后，再次读取 contact.txt 并建立哈希表。


7. 退出
~~~~~~~~
1. 输出“退出程序！”。
2. 调用 WriteData 保存当前联系人数据。
3. 直接返回 0，结束程序。


七、文件保存流程
----------------
调用：WriteData

1. 以输出方式打开 contact.txt。
2. 遍历 53 个桶，统计当前哈希表中的联系人总数。
3. 将联系人总数写入文件第一行。
4. 再次遍历所有桶。
5. 按照“姓名 电话 地址”的格式逐行写入联系人。
6. 关闭文件。

程序下一次启动时，会重新读取该文件，从而实现联系人数据持久化。


八、清空哈希表流程
------------------
调用：ClearHash

1. 逐个遍历 53 个桶。
2. 遍历每个桶中的联系人链表。
3. 逐个保存下一个节点地址。
4. 删除当前节点，直到链表为空。
5. 将桶头结点的 next 设置为空。
6. 将桶头结点的 st 恢复为 0。

十、当前程序的实现说明
----------------------
1. 程序使用链地址法处理哈希冲突，没有采用开放定址法。
2. 哈希表容量固定为 53。
3. 查询支持姓名和电话号码两种关键字。
4. 查询失败后支持基于字符串包含关系的模糊查询。
5. 支持联系人添加、查询、删除、显示和平均搜索长度统计。
6. README 中提到修改功能，但当前菜单和源代码中没有独立的修改操作。
7. 当前添加操作始终按姓名计算哈希地址；在电话查询模式下，这可能导致新添加联系人按电话号码查询时无法定位到正确桶。
8. contact.txt 中地址使用不含空格的连续字符串读取，因此地址字段不能包含空格。
9. main 中动态申请的 Buckets 数组以及每个桶的头结点在正常退出路径中没有统一 delete，但联系人节点在切换查询方式时会由 ClearHash 释放。
